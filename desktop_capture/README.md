# PC 上位机

1. Windows 设置中配对 JDY-34，确认系统生成蓝牙虚拟 COM 口。
2. 安装依赖：`python -m pip install -r requirements.txt`
3. 启动：`python main.py`
4. 选择 JDY-34 对应 COM 口并连接；成功时日志应出现 `PONG`。

Windows 通常会为经典蓝牙 SPP 创建一对端口。请选择界面中标为“传出/设备”的端口，不要选择“传入，不用于主动连接”的端口。只有收到 STM32 返回的 `PONG` 后，界面才会显示“设备已连接”。

如果只有 JDY-34 的传入端口：打开 Windows“更多蓝牙设置”中的“COM 端口”页，点击“添加”，选择“传出（计算机初始化连接）”，再选择 `JDY-34S-SPP` 的串行端口服务。新增的 COM 才是 PC 上位机应使用的端口。

当前这台电脑已由 Windows“COM 端口”页确认：`COM12` 是 JDY-34 的传出端口，`COM13` 是 JDY-34 的传入端口，因此上位机应选择 `COM12`。端口号在重新配对后可能变化，届时仍以 Windows 页面显示为准。

界面通过 9600 8N1 文本协议控制 STM32。滑块使用 120 ms 防抖，所有 `SET` 完成后统一发送 `APPLY`。

## 参数表模式

可加载 UTF-8 CSV 或 `.xlsx`。必填列为 `HMAX, HC, BR, BS`；其余设备参数列可省略，省略时使用默认值。`SAMPLE_ID` 为采集编号，只用于界面显示，不发送到设备。

- 手动模式：点击“上一条”或“下一条”。
- 定时模式：设置每行保持秒数后点击“开始定时”。计时从设备返回 `STATUS`、确认当前行已经应用后开始。
- 当前行编号、采集编号和完整参数会实时显示。

示例文件：`parameter_table_template.csv`。

## 有线 ADB 自动拍照

这版不需要安装 Android App。电脑仍通过 JDY-34 控制 STM32，手机通过 USB ADB 拍照；上位机是唯一的采集编号来源。

1. 在 Android“开发者选项”中打开“USB 调试”，用数据线连接电脑，并在手机上允许这台电脑调试。
2. 确认 `adb devices -l` 中手机状态为 `device`。如果 ADB 不在 `PATH`，在界面中选择 `adb.exe`。
3. 先加载参数表、连接 STM32，等待日志出现 `PONG`。
4. 在“有线 ADB 自动拍照”区点击“检测手机”，再点“测试拍照”。测试照片保存在输出目录的 `test` 子目录。
5. 测试成功后点击“开始/断点续拍”。固件返回且核心参数与当前表格行一致后，上位机才开始稳定等待和拍照；尾部扩展字段即使被蓝牙链路省略，也不会造成死锁。

“参数表模式”中的定时按钮只会定时切换波形，不会拍照；批量拍照必须点击 ADB 区域中的“▶ 开始自动拍照”。两种流程不能同时运行，启动自动拍照时会自动停止普通定时输出。左侧控制区、右侧日志区均带滚动条，ADB 状态也会常驻窗口顶栏。

9600 波特率下完整 `STATUS` 的发送时间超过 0.1 秒，上位机使用跨超时字节缓存，只有收到换行后才解析整行，避免把前半行误判为完整状态。若先收到上一组的旧状态，会自动再次读取。点击“停止”会立即取消当前 ADB 子进程并恢复界面，无需等待拍照或回传超时。

早期 HYST-V1 固件自身的 `HAL_UART_Transmit` 超时也是 100 ms，可能在完整状态发完前主动截断且不发送换行。上位机会在串口静默 250 ms 后识别这种旧固件半行：核心字段及所有实际收到的字段均匹配当前行才继续，旧行状态仍会被拒绝。当前源码及 `Output/atk_f407.hex` 已将固件发送超时延长到 500 ms。

默认用 Android `KEYCODE_CAMERA` 触发快门。如果手机相机不响应，选择“屏幕坐标”，打开手机的“指针位置”开发者选项查看快门按钮的 X/Y 坐标并填入。正式采集前请在相机中设为 JPEG，并尽量锁定曝光、对焦、白平衡和焦距。

输出结构：

```text
dataset/
├── images/
│   ├── IMG_0001.jpg
│   └── IMG_0002.jpg
├── parameters.csv
└── manifest.csv
```

`manifest.csv` 每拍完一张立即追加一行，记录参数、手机原文件名、时间和错误。再次开始时，上位机会核对 `status=ok` 且图片确实存在，只补拍缺失项。拍摄失败会按“重试”次数重试，仍失败则停止，避免参数和照片继续错位。

不同品牌相机保存扩展名可能是 `.jpg`、`.heic` 等；上位机会保留真实扩展名并在 manifest 中写入准确路径。批量数据集建议先在相机设置中关闭 HEIF/高效图片格式。

针对 HYST-V1 固件逐条校验 `HC<HMAX` 和 `BR<BS` 的行为，上位机会先临时放宽 HMAX/Bs，再按安全顺序写入目标值，避免跨行时出现 `ERR RANGE` 后沿用旧参数。MediaStore 查询也兼容不支持 `--sort`、却错误返回成功状态的部分小米系统。

若蓝牙链路丢失某条 `SET`，状态核对会指出具体不一致字段，并自动重新下发当前行的完整参数，而不是只反复读取同一个错误状态。重试期间绝不会拍照或跳到下一组；链路恢复后自动继续。

手机拍照、MediaStore 查询、照片回传或 USB ADB 暂时失败时，上位机会采用退避等待，自动重新检测手机、打开相机并重拍当前组。只有用户点击“停止”才终止任务；等待恢复期间仍可随时立即停止。

每次参数下发都由 2.5 秒事务看门狗监督：收到 `ERR COMMAND`、`ERR RANGE` 等设备错误，或完全收不到 `STATUS` 时，会清除尚未发送的旧命令并自动重发当前整组参数。这样即使错误发生在没有任何状态回包的阶段，也不会静默停住。

重试时参数表当前行是唯一目标值。设备返回的旧值或错误值只参与比较，不会覆盖界面中的待发送参数；因此不会发生“收到错误值后又把同一个错误值无限重发”的反馈循环。

新版固件提供 `CAPS`/`SETALL` 原子协议。上位机连接后自动探测：支持时，一组 12 个参数通过一条命令一次校验、一次提交，不再发送约 15 条容易丢失的独立 `SET`。日志出现“已启用 SETALL 原子协议”表示正在使用快速模式；需要烧录当前 `Output/atk_f407.hex`。

为避免误用，上位机禁止旧固件启动自动拍照。若连接后未检测到 `CAPS SETALL HYST-V2`，必须先烧录新版 HEX；普通手动控制仍可使用旧协议。快速模式每组日志应只有 `OK SETALL`，若看到连续十余条 `OK` 加 `OK APPLY`，说明实际仍是旧固件。

注意：通用 ADB 只能可靠地打开现有相机、触发快门和回传照片，不能跨品牌统一设置每一行的 ISO、曝光、焦距或白平衡。因此参数表中的电子波形变化可以全自动执行；需要逐行改变摄影条件的 `CAPTURE_INSTRUCTION` 仍需人工布置，或在第二阶段使用专用 CameraX 采集 App。
